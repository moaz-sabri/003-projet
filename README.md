# القالب التجاري الخفيف

> قالب ويب تجاري مستقل، قابل للتثبيت كتطبيق PWA، بواجهة عربية كاملة (RTL)،
> ولوحة إدارة لمدير واحد، وقاعدة بيانات SQLite واحدة.
> يبدأ كنموذج لمطعم/مقهى، ويتحوّل إلى أي نشاط آخر باختيار واحد عند التهيئة.

الإصدار 1.3 · PHP 8.1+ · SQLite · PWA · بلا مكتبات خارجية · بلا اشتراكات

**فكرة القالب:** بنية ثابتة لا تتغيّر، ومحتوى لا يتغيّر الكود.
- **المحتوى** (اسم، نبذة، صور، تواصل، أقسام) → ملف واحد: `app/data/company.json`
- **السلوك** (طلبات أم عرض فقط، تسميات، حقول) → نوع نشاط: `src/Config/BusinessPresets.php`

## 1. ما الذي يقدّمه هذا القالب

### للزبون

- **صفحة تعريف للشركة** (الرئيسية): غلاف، نبذة، نقاط تميّز، أقسام، معرض صور،
  وبيانات تواصل — كلها من ملف واحد. ثم صفحة **المنتجات**، وصفحة **تواصل معنا**.
- قائمة منتجات بالتصنيفات، بحث بسيط (شريطه داخل صفحة المنتجات لا فوقها)،
  وصفحة تفاصيل عند الحاجة فقط.
- وضعان يختارهما صاحب الموقع عند التهيئة:
  **مع نظام الطلبات** (سلة، إتمام، متابعة) أو **عرض فقط** (معرض بلا سلة ولا طلبات).
- تحديد الموقع من رمز QR، أو اختياره يدويًا إن لم يكن QR مفعّلًا.
- **رسالة واضحة بعد كل حدث**: أضيف إلى السلة، تم الحفظ، تعذّر الإرسال —
  بلون ونوع ورسالة قابلة للتراجع عن العمليات الحسّاسة.
- روابط نظيفة (`/products`، `/contact`، `/cart`، `/checkout`) تعمل مع زر الرجوع.
- تصميم واحد متناسق (فاتح وداكن) في الواجهة ولوحة الإدارة.
- تطبيق PWA قابل للتثبيت على الهاتف.
- **تصفح يعمل دون اتصال** للمنتجات التي جرت تحميلها، مع توضيح أن البيانات قديمة.
- **لا يمكن إرسال الطلب دون اتصال**، ولا يظهر أي تأكيد قبل حفظ الطلب فعليًا على الخادم.

### للمدير

- لوحة إدارة واحدة خفيفة: الرئيسية، التصنيفات، المنتجات، الطلبات، المواقع ورموز QR، إعدادات العرض.
- توليد رموز QR للمواقع وللطلبات محليًا (بدون أي خدمة خارجية مدفوعة)،
  وروابطها مختصرة ونظيفة تُطبع كما هي.
- صفحة طباعة جاهزة لكل رموز المواقع، وزر «نسخ الرابط» لكل موقع.
- نوافذ تأكيد وسؤال مصمّمة بدل نوافذ المتصفح، ورسالة بعد كل عملية.
- تحديث دوري للطلبات الجديدة (بدون WebSocket).
- نسخة احتياطية بضغطة واحدة، وتنزيلها من اللوحة.
- تغيير كلمة المرور، وتعديل الاسم والشعار ورسالة الترحيب.

### للمطوّر

- بدون Composer، بلا npm، بلا خطوة بناء — انسخ الملفات وارفعها.
- مولّد رموز QR كامل بلغة PHP خالصة (ISO/IEC 18004، مع Reed–Solomon).
- مولّد أيقونات PWA بصيغة PNG بلا GD (كتابة PNG يدوية).
- قاعدة بيانات SQLite واحدة بمعاملات واستعلامات محضّرة.
- 300+ اختبارًا آليًا تغطي معايير القبول (`php tests/run.php`).
- روابط نظيفة بلا أسماء ملفات داخلية: `/cart` و `/checkout` و `/order/{رمز}`،
  ورابط واحد للموقع (`/`) يعمل على جذر النطاق وداخل مجلد فرعي.

## 2. التشغيل السريع

### أ) التطوير محليًا — Docker (الطريقة المعتمدة)

كل بيئة تطوير تُشغَّل بالحاوية نفسها المستخدمة في الإنتاج، فتطابق النتائج
ولا تختلف بين جهازك وبين الاستضافة.

```bash
# 1) بناء الحاوية وتشغيلها على المنفذ 8080
docker compose up -d --build

# 2) تهيئة النسخة (داخل الحاوية)
docker exec light-commerce php bin/console install \
     --url=http://localhost:8080 --user=admin --pass="كلمة_مرور_قوية"

# 3) توليد الأيقونات + بيانات تجريبية (اختياري)
docker exec light-commerce php bin/console icons
docker exec light-commerce php bin/console seed:demo
```

| الوجهة | الرابط |
| --- | --- |
| واجهة الزبون | <http://localhost:8080/> |
| لوحة الإدارة | <http://localhost:8080/admin/> |

**أوامر التطوير المتكررة:**

```bash
docker compose logs -f app                             # سجل الخادم
docker exec light-commerce php tests/run.php        # 300+ اختبارًا
docker exec light-commerce php tools/security-probe.php http://127.0.0.1:8080
docker exec light-commerce php bin/console status   # حالة النسخة
docker exec light-commerce php bin/console security:check  # فحص حماية البيانات
docker compose down                                     # إيقاف
```

> **لماذا Docker محليًا؟** اختلاف بيئات الخادم هو ما أنتج ثلاثة عيوب في
> مراجعة سابقة: عيوب تعمل على خادم PHP المدمج وتفشل على Apache.
> نفس الصورة في كل مكان = لا مفاجآت.

### أ-2) بديل سريع بلا Docker (للاستعراض فقط)

```bash
php bin/console install --url=http://localhost:8000 --user=admin --pass="كلمة_مرور_قوية"
php bin/console icons
php -S localhost:8000 bin/serve.php
```

> `bin/serve.php` راوتر يحاكي قواعد الحماية برمجيًا لأن خادم PHP المدمج
> لا يقرأ `.htaccess`. **لا تعتمد عليه للاختبار النهائي.**

## 3. النشر على استضافة عادية (nginx)

**المتطلبات:** PHP 8.1+ مع `pdo_sqlite`، و nginx + PHP-FPM.
لا Composer ولا npm ولا خدمات خارجية.

| المتطلب | الحد الأدنى | ملاحظة |
| --- | --- | --- |
| PHP | 8.1 | مُختبَر على 8.3 و 8.4 |
| SQLite3 + PDO | مع الإصدار | `pdo_sqlite` |
| mbstring | مطلوب | للعرض العربي الصحيح |
| GD (اختياري) | غير مطلوب | لتوليد الصور فقط |
| fileinfo | مدمج | للتحقق من نوع الصورة |

تأكد من `pdo_sqlite`:
```bash
php -m | grep pdo_sqlite
```

### خطوات النشر

1. **ارفع ملفات المشروع** إلى مجلد الموقع (مثال: `public_html`).

2. **أنشئ مجلدات التخزين** بصلاحيات الكتابة:
   ```bash
   mkdir -p storage/database storage/config storage/logs storage/tmp storage/backups
   chmod -R 775 storage
   ```

3. **ثبّت النسخة** — إما عبر صفحة التهيئة `https://your-site.com/setup/`
   (واحذف `setup/` بعدها)، أو من الطرفية:
   ```bash
   php bin/console install --url=https://your-site.com --user=admin --pass="كلمة_مرور_قوية"
   ```

4. **اضبط رابط الموقع** في `storage/config/local.php` (يُستخدم في رموز QR):
   ```php
   'app' => ['base_url' => 'https://your-site.com'],
   ```

5. **فعّل HTTPS** — بدونه تبقى جلسة المدير بلا علامة `Secure`.

### ⚠️ أهم خطوة: حماية البيانات على nginx

**nginx لا يقرأ ملفات `.htaccess` إطلاقًا**، وعلى أغلب الاستضافات لا يمكنك
إضافة قواعد لكل مجلد. النتيجة المحتملة: رابط عام لقاعدة البيانات.

```
https://your-site.com/storage/database/app.sqlite   ← ينزّل كل الطلبات وأسماء الزبائن
```

القالب يفحص هذا تلقائيًا عند التثبيت **ويمنع إتمام التهيئة** إن كانت البيانات
مكشوفة، لكن الحل النهائي هو نقلها خارج مجلد الموقع:

```bash
php tools/move-outside-webroot.php          # عرض الخطة
php tools/move-outside-webroot.php --yes    # تنفيذ
```

تنقل الأداة ما يلي خارج `public_html` وتحدّث المسارات والصلاحيات تلقائيًا:

| من | إلى |
| --- | --- |
| `storage/config/local.php` | `../private-config/local.php` |
| `storage/database/app.sqlite` | `../private-data/app.sqlite` |

ثم تحقّق:

```bash
php bin/console security:check   # يجب أن يقول: البيانات محميّة ✔
```

> **ملاحظة:** لا تنقل `app/uploads/` — صور المنتجات يجب أن تصل إلى المتصفح.
> عند حذف المجلدات غير المستخدمة من النسخة المنشورة (`bin/ tests/ tools/`)
> تصبح الشيفرة أيضًا غير مقروءة للزوار.

### إن كان المضيف يتيح تعديل إعدادات nginx

أضف هذه القواعد بدل النقل (ولا تنسَ نقل البيانات للاحتياط):

```nginx
location ~ ^/(storage|src|bin|tests|tools|docs)/ { deny all; return 404; }
location ~ \.php$                                  { return 404; }
location ^~ /app/uploads/                          { autoindex off; }
```

### الروابط (كيف تُقدَّم الصفحات)

| الرابط | الصفحة |
| --- | --- |
| `/` | القائمة (ووجهة رموز QR: `/?loc=CODE`) |
| `/cart` | السلة |
| `/checkout` | إتمام الطلب |
| `/success` | تأكيد الطلب |
| `/order/{رمز}` | متابعة الطلب |
| `/product/{رقم}` | القائمة مع فتح منتج |
| `/admin/` | لوحة الإدارة |

القاعدة: `index.php` في الجذر هو ما يقدّم واجهة الزبون لكل هذه المسارات،
ويحوّل المسارات النسبية في القالب إلى مسارات مطلقة تحسبًا من موضعه،
لذلك يعمل القالب على جذر النطاق وداخل مجلد فرعي بلا تعديل.

- الرابط القديم `/app/index.html` يوجّه تلقائيًا إلى الجذر (301) مع الحفاظ
  على `?loc=`، فتبقى رموز QR المطبوعة سابقًا صالحة.
- إن كان الخادم لا يوجّه المسارات (استضافة nginx بلا إعدادات)، يتحوّل
  التطبيق تلقائيًا إلى وضع الهاش (`/#/cart`) بدل أن يفتح رابط 404 للزبون.
- المسارات التي تبدو كملفات (صورة أو سكربت مفقود) تردّ بـ 404 حقيقي،
  فلا تتحوّل أخطاء الأصول إلى صفحات HTML.

### طبقة البيانات

| الجدول | المحتوى |
| --- | --- |
| `settings` | إعدادات العرض القابلة للتعديل من اللوحة |
| `categories` | التصنيفات وترتيبها وحالتها |
| `products` | المنتجات والأسعار والصور والحقول الإضافية (JSON) |
| `locations` | المواقع (طاولات/معارض) ورموزها |
| `orders` | الطلبات: الرقم، الزبون، الموقع، الحالة، الإجمالي، مفتاح التكرار |
| `order_items` | عناصر الطلب مع **لقطة** الاسم والسعر وقت الطلب |
| `order_events` | سجل تغييرات الحالة |
| `daily_counters` | ترقيم الطلبات لكل يوم |
| `login_attempts` | محاولات تسجيل الدخول (لتقييد المحاولات) |

> كل الأسعار تُخزَّن كأعداد صحيحة (`price_minor`) لتفادي أخطاء الفاصلة العائمة،
> وكل التواريخ تُكتب بتوقيت النسخة عبر `Database::now()` (لا UTC).

## 5. تخصيص القالب لمشروع آخر

> 📘 **تريد دليلًا خطوة بخطوة؟** ابدأ من
> [`docs/BUILD_GUIDE.md`](docs/BUILD_GUIDE.md) — رحلة البناء الكاملة،
> وخريطة الملفات (ما يبقى وما يُحذف)، وكيف تضيف ميزات جديدة.

التخصيص على مستويين منفصلين تمامًا:

| ماذا تريد أن تتغير؟ | من أين |
| --- | --- |
| **محتوى** الشركة: الاسم، النبذة، الصور، التواصل، الأقسام | `app/data/company.json` — ملف واحد، بلا كود |
| **سلوك** المشروع: هل فيه طلبات؟ ما تسميات المنتجات؟ ما حقول التفاصيل؟ | `src/Config/BusinessPresets.php` — نوع نشاط جاهز |

### أ. المحتوى: ملف واحد

صفحتا **الرئيسية** و**تواصل معنا** تُبنىان بالكامل من `app/data/company.json`.
عدّله بعد الرفع فتتغيّر الصفحتان فورًا — لا قاعدة بيانات ولا لوحة إدارة.

الشرح الكامل لكل مفتاح: [`app/data/README.md`](app/data/README.md).

مثال مختصر:

```json
{
  "brand":   { "name": "معرض النور", "tagline": "سيارات مستعملة بضمان" },
  "about":   { "summary": "أكثر من 200 مركبة مفحوصة، كلها بضمان سنة." },
  "contact": {
    "phone": "03 123 456",
    "whatsapp": "96170123456",
    "instagram": "@noor.cars",
    "working_hours": [ { "day": "السبت — الخميس", "open": "10:00", "close": "19:00" } ]
  },
  "sections": [
    { "icon": "shield", "title": "ضمان سنة", "body": "فحص كامل قبل التسليم." }
  ]
}
```

> الملف اختياري تمامًا: احذفه أو أفسده ولا يسقط الموقع — تعود الصفحتان
> لإعدادات افتراضية. والقاعدة الذهبية: **الملف يملأ ما هو موجود في القالب،
> ولا يضيف قدرات جديدة.** لإضافة قسم جديد عدّل القالب لا الملف.

### ب. السلوك: اختر نوع النشاط عند التهيئة

صفحة التهيئة (`/setup/`) تسأل سؤالًا واحدًا: **ما نوع نشاطك؟**
وكل بطاقة تحدّد معًا: هل يوجد نظام طلبات أم لا، التسميات، أنواع الطلبات،
وأنظمة المواقع، وحقول تفاصيل المنتج.

| النوع | الوضع | التسميات | ملاحظة |
| --- | --- | --- | --- |
| `restaurant` | مع الطلبات | صنف / الأصناف | طاولات برموز QR، في المحل / سفري / توصيل |
| `store` | مع الطلبات | منتج / المنتجات | توصيل واستلام، بلا مواقع |
| `clinic` | مع الطلبات | خدمة / الخدمات | حجز موعد |
| `studio` | مع الطلبات | خدمة / الخدمات | طلب خدمة |
| `showroom` | **عرض فقط** | مركبة / المركبات | حقول سنة وقطعة وحالة |
| `general` | **عرض فقط** | منتج / المنتجات | الافتراضي |

لتغييره بعد التهيئة:

```bash
php bin/console preset list               # عرض الأنواع المتاحة
php bin/console preset show               # النوع الحالي
php bin/console preset apply showroom     # التبديل
```

### ماذا يفعل وضع "عرض فقط"؟

ليس مجرد إخفاء زر — الوضع يغيّر القالب فعليًا:

| | مع الطلبات | عرض فقط |
| --- | --- | --- |
| سلة وزر عائم وشاشات السلة | ✅ | ❌ مُخفيّة من الواجهة |
| `order.create` و `order.status` | تعمل | **تردّ 404 من الخادم** |
| زر "أضف" في بطاقة المنتج | ✅ | ❌ البطاقة تُفتح للتفاصيل فقط |
| تبويب الطلبات والمواقع في الإدارة | ✅ | ❌ مُخفيّان |
| صفحة التواصل | ✅ | ✅ (القناة الوحيدة للاستفسار) |

> الرفض في الخادم هو الحماية الحقيقية. إخفاء الزر في الواجهة ليس حماية:
> أي زائر يستطيع إرسال `POST` مباشرة إلى الـ API دون فتح الواجهة أصلًا.

### ج. تعديل أعمق: ProjectConfig

`ProjectConfig` ما زال المرجع النهائي، وأنواع النشاط تغلّفه فقط.
عدّله مباشرة عندما تريد شيئًا خارج ما تغطيه الأنواع الجاهزة:

```php
// أ. الهوية
public const DEFAULT_APP_NAME  = 'معرض النور';
public const CURRENCY           = 'ر.س';

// ب. تسمية الموقع
public const LOCATION_SINGULAR  = 'سيارة';
public const LOCATION_PLURAL    = 'سيارات';

// ج. حقول المنتج
public const PRODUCT_EXTRA_FIELDS = [
    ['key' => 'year',     'label' => 'سنة الصنع', 'type' => 'number', 'show_in_card' => true],
    ['key' => 'mileage',  'label' => 'المقطوعة',  'type' => 'text',   'show_in_card' => true],
];

// د. أنواع الطلبات
public const ORDER_TYPES = [ /* ... */ ];
```

> **القاعدة:** كل بنية قابلة للتغيير تُقرأ عبر **دالة** في `ProjectConfig`
> (`mode()`، `productSingular()`، `locationSingular()`…) لا عبر الثابت مباشرة.
> هذا ما يسمح لطبقة التغطية أن تعمل. إن أضفت ثابتًا جديدًا، أضف له دالة تقرأ منه.

> بعد تغيير أسماء الحقول بنيويًا: `php bin/console migrate:fresh`

## 6. الأمان

| المجال | الإجراء المطبَّق |
| --- | --- |
| كلمة مرور المدير | `password_hash()` (bcrypt/argon) في `storage/config/local.php` خارج المسارات العامة |
| الجلسات | كوكي `HttpOnly` + `SameSite=Strict` + `Secure` (مع HTTPS) + تجديد المعرّف بعد الدخول + انتهاء خمول ٢ ساعة |
| محاولات الدخول | قفل بعد 6 محاولات فاشلة لمدة 15 دقيقة |
| CSRF | رمز مرتبط بالجلسة مطلوب في كل عملية تعديل |
| SQL Injection | استعلامات محضّرة (PDO) في كل مكان |
| XSS | إخراج نصي مُهرَّر في الواجهتين + `strip_tags` على مدخلات الزبون |
| تلاعب بالأسعار | الخادم يحسب الإجمالي من قاعدة البيانات ويتجاهل أي سعر يرسله العميل |
| رفع الملفات | فحص النوع الحقيقي عبر `getimagesize` + حجم + أبعاد + اسم عشوائي + منع التنفيذ |
| الوصول للملفات | `nginx.conf` (Docker)، أو `.htaccess` على Apache، أو — على nginx بلا صلاحيات — نقل `storage/` خارج `public_html` بـ `tools/move-outside-webroot.php` |
| حماية المتصفح | CSPصارمة للوحة الإدارة + `nosniff` + `frame-ancestors 'none'` |
| الطلبات | حد ٢٠ طلب/دقيقة لكل عنوان IP + رفض.location غير صالح على الخادم |
| تكرار الطلبات | مفتاح `Idempotency-Key` + قيد فريد في قاعدة البيانات |
| رموز المتابعة | 32 محرفًا عشوائيًا من `random_bytes` + صلاحية محدودة زمنيًا |
| الأسرار | مستثناة في `.gitignore` — لا تُرفع أبدًا |

curl -I https://your-site.com/src/Config/ProjectConfig.php

## 7. النسخ الاحتياطي والاستعادة

### من لوحة الإدارة

**الأمان والنسخ ← إنشاء نسخة الآن** ثم **تنزيل**.

### من الطرفية

```bash
php bin/console backup      # ينشئ storage/backups/backup-YYYYmmdd-HHMMSS.sqlite
```

تُنشأ النسخة عبر `VACUUM INTO`، أي نسخة سليمة حتى أثناء العمل.
صلاحيات الملف `600` والمجلد محمي من الوصول عبر الويب.

### الاستعادة

1. أوقف الاستقبال مؤقتًا (اختياري).
2. انسخ ملف النسخة إلى `storage/database/app.sqlite`.
3. احذف `app.sqlite-wal` و `app.sqlite-shm` إن وُجدا.
4. أعد التشغيل.

نصيحة: اجعل نسخة يومية تلقائية عبر Cron:

```cron
0 3 * * * cd /path/to/project && php bin/console backup > /dev/null
```

## 9. واجهة الـ API

كل المسارات على `api/index.php?r=<المسار>`، وتعيد دائمًا:

```json
{ "ok": true, "data": { } }
{ "ok": false, "error": { "code": "نطاق_المشكلة", "message": "رسالة عربية" } }
```

### مسارات عامة

| المسار | الطريقة | الوظيفة |
| --- | --- | --- |
| `catalog.snapshot` | GET | الإعدادات + التصنيفات + المنتجات + المواقع (يُخزَّن للعمل دون اتصال) |
| `product.get&id=` | GET | تفاصيل منتج |
| `locations.list` | GET | المواقع النشطة |
| `order.create` | POST | إنشاء طلب (يتطلب `Idempotency-Key`) |
| `order.status&token=` | GET | متابعة حالة طلب (قراءة فقط) |
| `ping` | GET | فحص التشغيل |

**مثال إنشاء طلب:**

```bash
curl -X POST "https://your-site.com/api/index.php?r=order.create" \
  -H "Content-Type: application/json" \
  -H "Idempotency-Key: 4f2c9a11-6b1e-4c2f-9f11-2a0f2b3c4d5e" \
  -d '{
        "order_type": "dine_in",
        "customer_name": "أبو علي",
        "location_code": "T05",
        "fields": { "notes": "بدون بصل" },
        "items": [ { "product_id": 3, "quantity": 2 } ]
      }'
```

> `items` لا تحتوي أي سعر — الخادم هو المرجع الوحيد للأسعار.
> إعادة الإرسال بنفس `Idempotency-Key` تعيد الطلب نفسه دون تكرار.

### مسارات الإدارة

كلها تتطلب جلسة صالحة، وكل عملية تعديل تتطلب ترويسة `X-CSRF-Token`:

`admin.login` · `admin.logout` · `admin.session` · `admin.password` ·
`admin.dashboard` · `admin.orders.active` · `admin.orders` · `admin.order` ·
`admin.order.status` · `admin.order.qr` · `admin.qr` · `admin.qr.sheet` ·
`admin.categories` · `admin.category.create|update|delete` · `admin.categories.reorder` ·
`admin.products` · `admin.product.create|update|delete|image` ·
`admin.locations` · `admin.location.save|delete` · `admin.settings` ·
`admin.settings.update|export` · `admin.backups` · `admin.backup.create|download`

> `admin.settings.export` هو **POST** لا GET (عملية تُعدّل الحالة ⇒ CSRF إلزامي)،
> ويُخرج إعدادات **مبهمة**: بلا `password_hash` ولا `app_key`.

## 11. المشاكل الشائعة

**الصفحة تحوّلك إلى `setup`**
ملف `storage/config/local.php` غير موجود. نفّذ `php bin/console install`
أو افتح `setup/index.php`.

**"حدث خطأ في الخادم" بعد التحديث**
نفّذ `php bin/console migrate` — قد يكون مخطط قاعدة البيانات قديماً.

**رموز QR لا تعمل**
تأكد أن `base_url` في `storage/config/local.php` هو رابطك الحقيقي العام
(https ونطاق صحيح). الرابط المُطبوع هو `https://your-site.com/?loc=CODE`
(أو `https://your-site.com/order/رمز` للطلبات). جرّب الرابط المكتوب تحت
الرمز في اللوحة.

**رابط مباشر مثل `/cart` أو `/order/...` يعطي 404**
الروابط النظيفة تحتاج أن يوجّه الخادم كل مسار غير موجود إلى `index.php`:

- **Apache:** ملف `.htaccess` المرفق في جذر المشروع يتكفّل بذلك (شرط أن
  يكون `mod_rewrite` مفعّلًا و`.htaccess` مسموحًا).
- **nginx:** القواعد المرفقة في `docker/nginx.conf` تفعل ذلك عبر
  `try_files $uri $uri/ @shop;`. إن لم يكن بإمكانك تعديل إعدادات الخادم،
  يتحوّل التطبيق تلقائيًا إلى وضع الهاش (`/#/cart`) ويستمر كالمعتاد.

للتأكد سريعًا: افتح `https://your-site.com/cart` — يجب أن تفتح السلة، لا
صفحة خطأ.

**الصور لا تظهر**
تأكد أن `app/uploads/` قابلة للكتابة (775) وأن الخادم يسمح بعرض PNG/JPG.

**الطلبات لا تصل إلى اللوحة**
تأكد أن الطلب يُرسل عبر HTTPS وأن الخادم لا يحجب `api/index.php`،
وأن صلاحية الكتابة على `storage/database/` متاحة.

**الترميز العربي مشوّه**
تأكد أن `default_charset = UTF-8` وأن كل ملفات المشروع محفوظة UTF-8 دون BOM.

**الزبون يرى رسالة "لا يوجد اتصال" مع وجود الإنترنت**
تعطّل الخادم مؤقتًا أو فيه خطأ في `api/index.php`. افحص
`storage/logs/app-YYYY-MM-DD.log`.

## ⚠️ تحقّق من أمان نشرك بعد الرفع

**أهم خطوة بعد التثبيت.** حماية قاعدة البيانات تعتمد على أن خادمك يمنع
الوصول إلى مجلد `storage/`.

> **على nginx تحديدًا:** nginx لا يقرأ `.htaccess` إطلاقًا، وعلى أغلب
> الاستضافات لا يمكن إضافة قواعد لكل مجلد. لذلك قد يصبح رابط قاعدة
> البيانات متاحًا للعموم دون أي رسالة خطأ.

### كيف تتأكد؟

```bash
php bin/console security:check
```

أو افتح هذا الرابط في المتصفح:

```
https://your-site.com/storage/database/app.sqlite
```

| النتيجة | المعنى |
| --- | --- |
| `ممنوع` أو `غير موجود` | ✅ البيانات محميّة |
| نزَّل ملفًا | ⛔ **بيانات مكشوفة — نفّذ أدناه فورًا** |

> أمر `install` وصفحة التهيئة يفحصان هذا تلقائيًا **ويوقفان التهيئة**
> إن كانت البيانات مكشوفة.

### الحل (يعمل على أي خادم)

```bash
php tools/move-outside-webroot.php --yes
php bin/console security:check
```

### إن أتاح المضيف تعديل إعدادات nginx

```nginx
location ~ ^/(storage|src|bin|tests|tools|docs)/ { deny all; return 404; }
location ~ \.php$                                  { return 404; }
```

### ملاحظة على كشف الشيفرة

إن ظهر في الفحص أن `bin/console` أو `tests/` قابلة للقراءة، فالبيانات
**محميّة** ولا خطر حقيقي (أنت صاحب هذه الشيفرة أصلًا). ولإخفائها احذف
هذه المجلدات من النسخة المنشورة.
