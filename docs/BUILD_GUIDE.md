## 1. الفكرة في جملة واحدة

> **البنية ثابتة، والمحتوى يُملأ، والسلوك يُختار.**

كل تخصيص في هذا القالب يقع في واحدة من ثلاث طبقات. إذا فهمت الطبقات،
ستعرف فورًا أي ملف تفتح لأي سؤال:

| الطبقة | ماذا تحدّد | كيف تعدّلها | تحتاج كودًا؟ |
| --- | --- | --- | --- |
| **المحتوى** | من أنت، ماذا تعرض، كيف تتواصل | ملف `app/data/company.json` | ❌ لا |
| **السلوك** | هل فيه طلبات؟ ما تسمياتك؟ ما حقولك؟ | اختيار نوع النشاط (6 أنواع جاهزة) | ❌ لا |
| **البنية** | العملة، المنطقة الزمنية، قواعد الأمان، الحقول المخصّصة | الكود في `src/Config/ProjectConfig.php` | ✅ نعم |

**النتيجة العملية:** ٨٠٪ من مشاريعك تُنجَز دون كتابة سطر كود واحد.

```
محتوى  →  ملف واحد          (أي مشروع يتغيّر اسمك ورقمك وصورك)
سلوك   →  اختيار واحد        (مطعم أم معرض أم عيادة؟)
بنية   →  تعديل الكود        (فقط حين لا يكفي ما سبق)
```

> ⚠️ **القاعدة التي لا تُخترق:** المحتوى والسلوك لا يضيفان قدرات جديدة.
> إذا أردت قسمًا جديدًا أو حقلًا لم يعرّفه القالب، فأنت تعدّل **القالب**
> لا الملف. الخلط بين الاثنين هو أشهر سبب لبناء موقع يحتاج صيانة دائمة.

## 2. أنواع المشاريع: اختر قبل أن تبني

القالب يوفّر ٦ أنواع نشاط جاهزة. كل نوع يحدّد دفعة واحدة: **الوضع والتسميات
وأنواع الطلبات وحقول التفاصيل والوظائف المفعّلة**.

| المعرّف | الاسم | الوضع | التسميات | المواضع | مثال استخدام |
| --- | --- | --- | --- | --- | --- |
| `restaurant` | مطعم أو مقهى | 🛒 مع الطلبات | صنف / الأصناف | ✅ طاولات | مطعم، مقهى، حلويات |
| `store` | متجر | 🛒 مع الطلبات | منتج / المنتجات | ❌ فروع | متجر ملابس، بقالة، كتب |
| `clinic` | عيادة أو مركز صحي | 🛒 مع الطلبات | خدمة / الخدمات | ❌ فروع | عيادة، صالون، مركز تدريب |
| `studio` | استوديو أو ورشة | 🛒 مع الطلبات | خدمة / الخدمات | ❌ مقرات | استوديو تصوير، ورشة، مكتب هندسي |
| `showroom` | معرض أو وكالة | 📖 عرض فقط | مركبة / المركبات | ❌ معارض | سيارات، عقارات، أثاث |
| `general` | عام — عرض فقط | 📖 عرض فقط | منتج / المنتجات | ❌ فروع | مؤسسة، علامة تجارية، أرشيف |

### ما الذي يتغيّر فعليًا بين «مع الطلبات» و«عرض فقط»؟

ليس إخفاء زر. **الوضع يغيّر القالب من الجذور:**

| | 🛒 مع الطلبات | 📖 عرض فقط |
| --- | --- | --- |
| سلة وزر عائم وشاشات السلة | ✅ | ❌ مخفيّة |
| `order.create` و `order.status` | تعمل | **تردّ 404 من الخادم** |
| زر «أضف» في بطاقة المنتج | ✅ | ❌ البطاقة تفتح للتفاصيل فقط |
| تبويب الطلبات والمواقع في الإدارة | ✅ | ❌ مختفيان |
| صفحة التواصل | ✅ | ✅ (القناة الوحيدة للاستفسار) |

> 🔐 **لماذا الرفض من الخادم هو الحماية الحقيقية؟**
> لأن إخفاء الزر في الواجهة ليس حماية. أي زائر يستطيع إرسال `POST`
> مباشرة إلى الـ API دون فتح الواجهة أصلًا. لذلك يرفض الخادم الطلب
> حتى لو أُرسل يدويًا من `curl`.

### اختيارك الأول يحدد نصف عملك

| إن كان نشاطك | اختر | لأن |
| --- | --- | --- |
| يبيع أو يحجز | `store` / `clinic` / `studio` | الزبون يحتاج سلة ويُنتظر منه فعل |
| يعرض خيارات ويستقبل استفسارات | `showroom` / `general` | الطلب بضاعة على الطاولة يسألها الزبون |
| جلس داخل المحل ويُطلب بالطاولة | `restaurant` | المشروع الوحيد الذي يحتاج مواقع و QR للمواقع |

> لا تختر نوعًا أكبر مما تحتاج. «معرض» لمحل جواهر أفضل من «متجر»:
> لن تجد سلة في واجهة معرض ولا زر طلب في لوحة إدارته.
> وإن اخترت نوعًا بالطلبات ثم لم تحتجه، يمكنك التحويل لاحقًا بأمر واحد.

## 3. رحلة البناء: ٧ مراحل

### المرحلة ١ — شغّل القالب محليًا أولًا (قبل أي تعديل)

```bash
docker compose up -d --build
docker exec light-commerce php bin/console install \
     --url=http://localhost:8080 --user=admin --pass="كلمة_مرور_قوية" \
     --preset=restaurant
docker exec light-commerce php bin/console icons
docker exec light-commerce php bin/console seed:demo
```

| الوجهة | الرابط |
| --- | --- |
| واجهة الزبون | <http://localhost:8080/> |
| لوحة الإدارة | <http://localhost:8080/admin/> |

> **لماذا Docker محليًا؟**
> اختلاف بيئات الخادم هو ما أنتج ثلاثة عيوب في مراجعة سابقة: عيوب تعمل على
> خادم PHP المدمج وتفشل على Apache. نفس الحاوية في كل مكان = لا مفاجآت.
>
> **لا تعدّل على الاستضافة مباشرة.** عدّل محليًا، اختبر، ثم ارفع.

### المرحلة ٢ — اختر نوع النشاط وجرّبه

```bash
php bin/console preset list      # ما المتاح
php bin/console preset show      # ما الحالي
php bin/console preset apply showroom
```

جرّب الوضعين عمليًا قبل أن تلتزم: افتح `/`، جرّب إضافة منتج، جرّب السلة
إن وُجدت، لاحظ التسمية في كل مكان. التبديل مجاني بالكامل.

### المرحلة ٣ — املأ محتوى الشركة

عدّل `app/data/company.json` فقط. الدليل الكامل لكل مفتاح في
[`app/data/README.md`](../app/data/README.md). ابدأ بهذه المفاتيح:

```json
{
  "brand":   { "name": "معرض النور", "tagline": "سيارات مستعملة بضمان" },
  "about":   { "summary": "أكثر من 200 مركبة مفحوصة، كلها بضمان سنة." },
  "contact": {
    "phone": "03 123 456",
    "whatsapp": "96170123456",
    "working_hours": [ { "day": "السبت — الخميس", "open": "10:00", "close": "19:00" } ]
  },
  "seo":     { "title": "معرض النور | سيارات مستعملة بضمان", "description": "..." }
}
```

> الملف **آمن تمامًا**: حذفه أو إفساده لا يُسقط الموقع — تعود الصفحتان
> لإعدادات افتراضية. جرّب بالملف ثم حسم قرارك.

### المرحلة ٤ — املأ البيانات الحقيقية

من لوحة الإدارة: **التصنيفات ← المنتجات ← (المواقع إن وُجدت)**.

- أضف التصنيفات أولًا ثم اربطها بالمنتجات.
- ارفع صورة لكل منتج من زر الرفع مباشرة.
- فعّل `seed:demo` للتجربة فقط — **احذف بياناته قبل الإطلاق** (المرحلة ٧).
- جرّب رفع صورة خبيثة باسم `x.php` لتتأكد أن الرفض يعمل.

### المرحلة ٥ — خصّص البنية إن لزم (اختياري)

عدّل `src/Config/ProjectConfig.php` فقط. أكثر ما يُعدَّل عادةً:

```php
// العملة
public const CURRENCY         = 'ر.س';
public const CURRENCY_POSITION = 'after';   // قبل أو بعد الرقم
public const CURRENCY_DECIMALS = 0;

// المنطقة الزمنية (مهمة لأوقات الطلبات وتقارير اليوم)
public const TIMEZONE = 'Asia/Riyadh';

// اسم ما يطلبه الزبون عند الإتمام
public const CUSTOMER_NAME_LABEL      = 'الاسم';
public const CUSTOMER_PHONE_REQUIRED  = false;
```

> ⚠️ بعد تغيير أسماء الحقول بنيويًا: `php bin/console migrate:fresh`

### المرحلة ٦ — اختبر كأنك عميل

| الاختبار | كيف | المتوقع |
| --- | --- | --- |
| الرابط المباشر | افتح `/cart` و `/checkout` مباشرة | تفتح، لا 404 |
| رمز QR | افتح `/?loc=T05` | القائمة تفتح والموقع محدّد |
| دون اتصال | أطفئ الشبكة وافتح الصفحة | المنتجات المحفوظة تظهر + شريط تنبيه |
| منع الإرسال دون اتصال | حاول إرسال طلب والشبكة مقطوعة | **مرفوض** بلا أي طلب في اللوحة |
| телеfon | افتح الموقع على هاتف حقيقي | لا تمرير أفقي، الأزرار كبيرة |
| الثيم الداكن | فعّل الوضع الداكن في نظامك | الألوان تتبدّل بلا كسر |

وشغّل الفحوص الآلية:

```bash
php tests/run.php                            # 300+ اختبار وحدة وتكامل
php tests/http/check.php http://localhost:8080
php tools/code-review.php
```

## 4. مستويات التخصيص الثلاثة

### المستوى ١ — المحتوى (بلا كود)

**الملف:** `app/data/company.json` · **متى:** كل مشروع بلا استثناء

يملأ صفحتَي **الرئيسية** و**تواصل معنا** بالكامل. بدون قاعدة بيانات
ولوحة إدارة — تعدّل الملف وتُحدِّث المتصفح.

| الكتلة | ما فيها |
| --- | --- |
| `brand` | الاسم، الشعار، الغلاف، صورة الغلاف العلوية |
| `about` | نبذة، قصة، ٣–٤ نقاط تميّز، معرض صور |
| `contact` | هاتف، واتساب، بريد، كل حسابات التواصل، عنوان، أوقات عمل |
| `sections` | كتل مرنة: عنوان + نص + نقاط + صورة + أيقونة |
| `cta` | شريط الدعوة للإجراء |
| `seo` | العنوان والوصف والكلمات — تعمل قبل تهيئة قاعدة البيانات |
| `footer` | سطر ختامي وروابط |

**الصور:** ثلاثة صيغ مقبولة لكل حقل صورة:

| الصيغة | متى |
| --- | --- |
| `"brand/logo.png"` (اسم ملف) | الطريقة الاعتيادية: ارفعه إلى `app/uploads/` |
| `"https://..."` (رابط كامل) | صورة مستضافة خارجًا |
| `"data:image/png;base64,..."` | للأيقونات الصغيرة فقط |

**أهم ٦ أيقونات متاحة** (وأي اسم غير مدرج يُتجاهل بصمت):

```
star · shield · clock · truck · check · heart · phone · mail
pin · calendar · award · sparkle · leaf · tool · tag · gift
users · chart · box · key
```

> ⚠️ **لا تضع في هذا الملف أي بيانات خاصة.** هو داخل مسار الويب، فمن يقرأ
> الموقع يقرأ الملف. لا أرقام هوية ولا أسعار جملة ولا كلمات مرور.

### المستوى ٢ — السلوك (بلا كود)

**المكان:** اختيار نوع النشاط · **متى:** عند التهيئة، أو لاحقًا بأمر واحد

كل نوع نشاط يحمل المعرّف التالي كاملًا — لا حاجة لتعديل أي ملف آخر:

```php
'store' => [
    'mode'            => 'orders',           // orders | catalog
    'product_singular' => 'منتج',             // التسميات
    'catalog_title'    => 'المنتجات',
    'order_cta'        => 'أكمل الطلب',
    'locations'        => ['enabled' => false, 'source' => 'disabled'],
    'order_types'      => [ /* توصيل، استلام … */ ],
    'extra_fields'     => [ /* sku, brand, featured */ ],
    'detail_fields'    => [ /* specs, warranty */ ],
    'features'         => ['locations' => false, 'order_tracking' => true],
],
```

**ماذا تحدّد `order_types`؟** لكل نوع: تسميته، أيقونته، هل يفرض موقعًا، وحقوله.

```php
'clinic' => [ 'visit' => [
    'label'     => 'حجز موعد',
    'default'   => true,
    'fields'    => [
        ['key' => 'customer_phone',       'label' => 'رقم الهاتف', 'type' => 'tel',   'required' => true],
        ['key' => 'appointment_date',     'label' => 'التاريخ',    'type' => 'text',  'required' => true],
        ['key' => 'appointment_time',     'label' => 'الوقت',      'type' => 'text',  'required' => false],
        ['key' => 'notes',                'label' => 'ملاحظات',    'type' => 'textarea'],
    ],
] ]
```

الأنواع المدعومة للحقل: `text` · `textarea` · `number` · `tel` · `select` · `boolean`

> 💡 **أضف نوع نشاط خاصًا بك = مدخل واحد فقط** في `BusinessPresets.php`.
> لا حاجة لتعديل أي ملف آخر — هذا مقصود من تصميم القالب.

### المستوى ٣ — البنية (بتعديل الكود)

**الملف:** `src/Config/ProjectConfig.php` · **متى:** حين لا يكفي ما سبق

| ماذا | المفتاح | القيم المعتادة |
| --- | --- | --- |
| العملة وموضعها | `CURRENCY` · `CURRENCY_POSITION` · `CURRENCY_DECIMALS` | `ل.ل` · `after` · `0` |
| المنطقة الزمنية | `TIMEZONE` | `Asia/Beirut` |
| اللغة والاتجاه | `LOCALE` · `DIRECTION` | `ar` · `rtl` |
| حدود الطلب | `MAX_ITEMS_PER_ORDER` · `MAX_QTY_PER_ITEM` | `40` · `99` |
| حد الإرسال | `ORDER_RATE_LIMIT_PER_MINUTE` | `60` |
| حالات الطلب | `ORDER_STATUSES` | جديد ← قيد التنفيذ ← مكتمل / ملغى |
| صلاحية رمز المتابعة | `ORDER_TOKEN_TTL_MINUTES` | أسبوعان |
| جلسة المدير | `ADMIN_SESSION_IDLE_MIN` · `ADMIN_MAX_LOGIN_ATTEMPTS` | `120` · `6` |
| حقول المنتج | `PRODUCT_EXTRA_FIELDS` · `PRODUCT_DETAIL_FIELDS` | حسب النشاط |
| الوظائف | `FEATURES` | ١٤ وظيفة بمفاتيح |

#### ⚠️ القاعدة التي تحمي طبقة التغطية

كل بنية قابلة للتغيير تُقرأ عبر **دالة** لا عبر الثابت مباشرة:

```php
// ✅ الصحيح — يسمح لطبقة التغطية أن تعمل
public static function productSingular(): string {
    return (string) self::ov('product_singular', 'صنف');
}

// ❌ خطأ — يُجمّد القيمة ويلغي أي تغطية لوقت التشغيل
$label = ProjectConfig::PRODUCT_SINGULAR;
```

> إن أضفت ثابتًا بنيويًا جديدًا، **أضف له دالة تقرأ منه**. هذا هو الشرط
> الذي يجعل اختيار نوع النشاط في صفحة التهيئة يعمل أصلًا.

#### تخصيصات بصرية سريعة

| تريد | افتح |
| --- | --- |
| لون الهويةaccent | `app/css/app.css` → متغيّرات `--accent` (الوضع الفاتح **و** الداكن معًا) |
| ألوان لوحة الإدارة | `admin/assets/admin.css` → نفس المتغيّرات |
| ألوان حالات الطلب | `ProjectConfig::ORDER_STATUSES` → `color` لكل حالة |
| الخط العربي | `app/css/app.css` → `--font` (كل الخطوط من النظام، بلا تنزيل) |

> 💡 **الوضع الداكن يبني على نظام المستخدم تلقائيًا** عبر
> `prefers-color-scheme`. لتغييره عندك، عدّل الكتلتين `:root` معًا.
> لا يوجد مفتاح تبديل يدوي، ولا صنف `.dark` — وهذا قرار مقصود.

## 5. كيف تضيف ميزة جديدة

### المسار ١ — حقل إضافي (الأسهل: دقائق)

أضف مدخلًا إلى `PRODUCT_EXTRA_FIELDS` أو `ORDER_TYPES[*]['fields']`:

```php
[
    'key'          => 'warranty',
    'label'        => 'الضمان',
    'type'         => 'text',          // text|textarea|number|tel|select|boolean
    'required'     => false,
    'default'      => '',
    'hint'         => 'مثال: سنة كاملة',
    'show_in_card' => true,            // يظهر في بطاقة المنتج
    'searchable'   => true,            // participates في البحث
    'sort'         => 10,              // ترتيب العرض
],
```

يظهر الحقل فورًا في **نموذج الإدارة** و**نموذج الإتمام** و**نتيجة الطلب**.
لا حاجة لأي ملف آخر. القيم تُخزَّن في `extra_json` فلا يمسّ المخطط.

### المسار ٢ — قسم في الصفحة الرئيسية

`sections` في `company.json` كتل مرنة — لا تحتاج كودًا:

```json
{ "icon": "award", "title": "لماذا تختارنا؟",
  "body": "نص الفقرة.", "bullets": ["نقطة أولى"], "image": "work/1.jpg", "flip": true }
```

> الكتلة الفارغة (بلا نص ولا صورة ولا نقاط) **لا تُعرض تلقائيًا**.
> جرّب بحرية ولا تحذف خوفًا من «المساحة».

### المسار ٣ — نوع طلب جديد

في `BusinessPresets.php` داخل نوع نشاطك:

```php
'pickup' => [
    'label'  => 'استلام من المحل',
    'icon'   => 'takeaway',
    'default' => false,
    'requires_location' => false,
    'fields'  => [ /* ... */ ],
],
```

### المسار ٤ — صفحة جديدة في الواجهة (تحتاج ٤ مواضع)

الواجهة صفحة واحدة (SPA) تُبدّل أقسامها. لإضافة `view-privacy`:

1. **القالب** — `app/index.html`: أضف `<section class="view" id="view-privacy">`.
2. **الأسماء** — `app/js/app.js`: أضف `'privacy'` إلى `VIEWS` وإلى `VIEW_TITLES`.
3. **التوجيه** — `app/js/app.js`: أضف `case 'privacy':` في دالة `render()`.
4. **الرسم** — `app/js/ui.js`: أضف `renderPrivacy()` واستدعها من `render()`.
5. **عنوان SEO** — `index.php`: أضف حالة العنوان (اختياري).

> ⚠️ **انتبه:** `index.php` يعيد كتابة كل `href` و `src` النسبية في القالب
> ليصبح مسارها مطلقًا. لذلك لا تكتب مسارات مطلقة `/...` داخل
> `app/index.html` إلا إن كنت تقصد جذر النطاق.

### المسار ٥ — مسار API جديد (الخيار الأقوى)

المسارات في ملفين منفصلين حسب الصلاحية:

| الملف | لمن | يفرض |
| --- | --- | --- |
| `api/routes/public.php` | الزوار | لا شيء (مع تقييد معدل) |
| `api/routes/admin.php` | المدير | جلسة + رمز CSRF |

أضف حالتك في المسار المناسب، وستكون محميًا بنفس القواعد
(استعلامات محضّرة، تحقق من المدخلات، حد معدل) بلا عمل إضافي.

### ⚠️ أضِف إلى الترويسة دائمًا

أي سكربت جديد لا بد من إضافته في ثلاثة مواضع وإلا لن يعمل:

| الموضع | لماذا |
| --- | --- |
| `<script src="js/xxx.js?v=1.3.0">` في `app/index.html` **قبل `app.js`** | السكربتات غير نمطية، الترتيب يهم |
| `SHELL_ASSETS` في `sw.js` | ليعمل دون اتصال |
| `?v=` في كل موضع — أو **رقم إصدار جديد** (انظر [المرحلة ١١](#11-التحديث-إلى-نسخة-القالب-الأحدث)) | لكسر كاش المتصفح |

> 🔒 **انتبه لـ CSP.** سياسة أمان المحتوى تُرفض أي `<script>` مضمّن بلا
> `nonce`، وتُرفض أي `onclick` مكتوبة داخل HTML. استخدم
> `addEventListener` في ملفات JS بدلًا من معالجات مضمّنة.

## 6. خريطة الملفات: ما يبقى وما يُحذف

> هذه أهم قائمة في الدليل. اقرأها مرتين: **قبل** البناء، و**بعد**ه.

### 🟢 يجب أن يبقى — حذفه يعني موقعًا مكسورًا

| المسار | لماذا لا يُحذف |
| --- | --- |
| `index.php` | نقطة الدخول الوحيدة لكل رابط نظيف (`/` و `/cart` و `/order/…`) |
| `sw.js` | عامل الخدمة — **يجب أن يكون في جذر النطاق** ليشمل `/api/` |
| `app/index.html` | قالب الصفحة الوحيد (٧ أقسام) |
| `app/manifest.webmanifest` | بيان التطبيق — بدونه لا يوجد PWA |
| `app/js/` · `app/css/` · `app/assets/icons/` | الواجهة والرسم والأيقونات |
| `app/uploads/` + `.htaccess` | **صور المنتجات** + منع تنفيذ أي سكربت فيها |
| `app/data/company.json` | محتوى الصفحتين الرئيسيتين |
| `admin/index.php` + `admin/assets/` | لوحة الإدارة كاملة |
| `api/index.php` + `api/routes/` | نقطة الدخول الوحيدة لكل المسارات |
| `src/bootstrap.php` | نقطة تحميل الكود |
| `src/Core/` | قاعدة البيانات · HTTP · الأمان · QR · المال · المسارات |
| `src/Config/` | `ProjectConfig` + `BusinessPresets` — **قلب التخصيص** |
| `src/Repositories/` + `src/Services/` | الوصول للبيانات ومنطق العمل |
| `src/.htaccess` | يمنع تقديم كود الخادم للمتصفح |
| `storage/.htaccess` | يمنع الوصول للقاعدة والنسخ والسجلات |
| `storage/config/local.php` | **بيانات الدخول** — لا بديل عنه |
| `storage/database/` · `backups/` · `logs/` · `tmp/` | بياناتك |
| `.htaccess` (الجذر) | الروابط النظيفة + منع الوصول + ترويسات الأمان |

> 🔴 **الملفات النقطة (`.htaccess`) هي الأخطر في هذا الجدول.**
> كثير من برامج FTP **تخفي الملفات التي تبدأ بنقطة افتراضيًا**.
> **فعّل خيار «إظهار الملفات المخفية»** قبل الرفع، وتأكد أن
> `src/.htaccess` و `storage/.htaccess` و `app/uploads/.htaccess`
> موجودة فعلًا بعد الرفع. بدونها: قاعدة بياناتك عامة.

### 🔴 يجب أن يُحذف بعد البناء — فورًا

| المسار | لماذا الحذف إلزامي |
| --- | --- |
| `setup/` | ⚠️ **الأخطر على الإطلاق.** صفحة التهيئة مفتوحة للجميع، تُعيد التهيئة وتمنح كلمة مرور المدير التي يُدخلها الزائر |

### 🟡 يمكن حذفه — يقلّل مساحة الموقع ويخفي الشيفرة

| المسار | بعد حذفه تفقد |
| --- | --- |
| `tests/` · `tests/http/` | الاختبارات الآلية — **احتفظ بها محليًا** |
| `tools/` | أدوات الفحص والصيانة (انظر التحذير أدناه) |
| `docs/` | التوثيق |
| `docker/` · `Dockerfile` · `compose.yaml` | بيئة التطوير — لا يحتاجها الإنتاج |
| `README.md` · `CHANGELOG.md` · `AUDIT_REPORT.md` | التوثيق (`security:check`чита عند حذفها) |
| `.env.example` | مرجع فقط — **القالب لا يقرأ `.env` أصلًا** |
| `test.md` | ملف فارغ |
| `src/Tools/DemoSeeder.php` | البيانات التجريبية |
| `storage/tmp/rate-*.json` | عدّادات المعدل — تُولَّد من جديد تلقائيًا |

> ⚠️ **ترتيب مهم جدًا:**
> 1. `tools/move-outside-webroot.php` **يعيش في `tools/`**. شغّله **أولًا**.
> 2. `bin/console` و `bin/serve.php` — اختياري:
>    حذفهما يُخفي الشيفرة، لكنك تفقد `backup` و `migrate` و `preset apply`
>    على الخادم. **قرار لك** — إن كان لك وصول SSH فاحتفظ بهما.

### ⚪ حالة خاصة — الأيقونات

`app/assets/icons/*.png` **مولَّدة محليًا** ومُستثناة من Git عمدًا.
على خادم لا تستطيع تنفيذ PHP؟ انسخ المجلد كما هو من نسختك المحلية.

| التبويب | ماذا تفعل فيه يوميًا |
| --- | --- |
| **الرئيسية** | ملخّص الطلبات الجديدة — ابدأ من هنا |

| **المنتجات** | إضافة/تعديل/حذف، الأسعار، الصور، التوفّر، الحقول الإضافية |
| **التصنيفات** | إضافة وترتيب بالسحب |

### دورة حياة الطلب

```
جديد  ──→  قيد التنفيذ  ──→  مكتمل
  │              │
  └──────────────┴──────→  ملغى
```

> الحالات والانتقالات معرَّفة في `ProjectConfig::ORDER_STATUSES`.
> **الإلغاء لا يحذف السجل** — بقيعة التدقيق تبقى، ولا يؤثر على طلب آخر
> في الموقع نفسه (كل طلب مستقل دائمًا).

### رموز QR — النوعان

| النوع | الرابط | الغرض |
| --- | --- | --- |
| **موقع** | `https://site.com/?loc=T05` | يفتح القائمة والموقع محدّد — **لا ينشئ طلبًا** |
| **طلب** | `https://site.com/order/{رمز}` | متابعة حالة طلب محدّد — للقراءة فقط |

> ⚠️ **الرابط المطبوع تحت الرمز هو المرجع.** إذا تغيّر `base_url`
> لاحقًا، الروابط القديمة توقّفت عن العمل — أعد التوليد والطباعة.
>
> **نصيحة طباعة:** طبّع الرابط ولا تعِد نشره على خادمك بلا HTTPS.

### تفاصيل قد تربك المستخدم الجديد

| ما ستلاحظ | السبب | ما تفعله |
| --- | --- | --- |
| الطلبات الجديدة لا تظهر تلقائيًا حتى إعادة الدخول | التحديث الدوري يبدأ بعد قراءة إعدادات اللوحة التي تصل بعد أول عرض | استخدم زر «تحديث»، أو سجّل خروجًا وادخل |
| أرقام عربية مقطوعة عند `CURRENCY_DECIMALS = 0` | 가격이 تُخزَّن كأعداد صحيحة | غيّر الثابت في `ProjectConfig` ثم أعد التهيئة |
| «تم إيقاف المحاولات مؤقتًا» بعد ٦ محاولات | قفل ١٥ دقيقة عند ٦ محاولات فاشلة | انتظر، أو امسح السجل |

> **ملاحظة مهمة:** زر «تحديث» في اللوحة يعيد تحميل العرض الحالي فقط.
> الطلبات لا تصل تلقائيًا على هاتفك قبل تحديث الصفحة. هذا سلوك مقصود —
> لا WebSocket ولا إشعارات لحظية، فlighter وأخف.

## 9. الأمان بعد النشر

> **هذه ليست خطوة اختيارية.** لا يُعتبر الموقع جاهزًا قبل أن يمرّ الفحص.

### ١ — فعّل HTTPS

بلا HTTPS تبقى جلسة المدير بلا علامة `Secure`. أغلب الاستضافات توفّر
شهادة مجانية.

### ٢ — شغّل فحص الحماية

```bash
php bin/console security:check
```

يفحص ٧ مسارات حسّاسة ويصنّف النتيجة:

| النتيجة | المعنى |
| --- | --- |
| `البيانات محميّة ✔` | ✅ ممتاز |
| `البيانات محميّة ✔` + «الشيفرة مقروءة للزوار» | ✅ مقبول — احذف `bin/` و `tests/` لإخفائها |
| `بيانات حسّاسة مكشوفة ✘` | ⛔ **توقف — أصلحها فورًا** |
| `تعذّر الفحص` | تحقّق من `allow_url_fopen` أو رابط الموقع |

> الأمر `install` وصفحة التهيئة يفحصان هذا تلقائيًا **ويوقفان التهيئة**
> إن كانت البيانات مكشوفة. الفحص postwar هو ما يغطّي ما بعد الرفع.

### ٣ — اختبر بنفسك

```bash
curl -I https://your-site.com/storage/database/app.sqlite
curl -I https://your-site.com/storage/config/local.php
curl -I https://your-site.com/src/Config/ProjectConfig.php
curl -I https://your-site.com/app/uploads/test.php
```

يجب أن يعيد الأربعة **403 أو 404**. أي `200` يعني مشكلة.

> 🔴 **على nginx تحديدًا:** nginx **لا يقرأ `.htaccess` إطلاقًا**، وعلى أغلب
> الاستضافات لا يمكنك إضافة قواعد لكل مجلد. النتيجة المحتملة: رابط عام
> لقاعدة البيانات — بلا أي رسالة خطأ. لذلك الأداة في الخطوة ١ ليست ترفًا.

### ٤ — إن أتاح المضيف تعديل إعدادات nginx

```nginx
location ~ ^/(storage|src|bin|tests|tools|docs)/ { deny all; return 404; }
location ~ \.php$                                  { return 404; }
location ^~ /app/uploads/                          { autoindex off; }
```

### ٥ — فحوص أخرى مفيدة

```bash
php tools/workflow-test.php https://your-site.com   # 69 خطوة سير عمل كامل
php tools/security-probe.php https://your-site.com  # 49 فحصًا أمنيًا حيًّا
php tests/http/check.php      https://your-site.com # 48 فحص نشر
```

> ⚠️ **شغّل الأدوات الحيّة على خادم تجريبي فقط.**
> `security-probe` تُرسل محاولات دخول فاشلة عمدًا فتُفعّل قفل المحاولات
> لـ ١٥ دقيقة على نسختك الحقيقية.

### ملخص ما يحميك القالب تلقائيًا

| المجال | الإجراء المطبَّق |
| --- | --- |
| كلمة مرور المدير | `password_hash()` في ملف خارج المسارات العامة |
| الجلسات | `HttpOnly` + `SameSite=Strict` + `Secure` + تجديد المعرّف بعد الدخول |
| محاولات الدخول | قفل بعد ٦ محاولات فاشلة لمدة ١٥ دقيقة |
| CSRF | رمز مرتبط بالجلسة في كل عملية تعديل |
| SQL Injection | استعلامات محضّرة في كل مكان |
| XSS | إخراج مهرَّر + `strip_tags` + CSP صارمة بـ `nonce` |
| **تلاعب بالأسعار** | الخادم يحسب الإجمالي من القاعدة ويتجاهل أي سعر من العميل |
| رفع الملفات | فحص النوع الحقيقي + حجم + أبعاد + اسم عشوائي + منع التنفيذ |
| تكرار الطلبات | `Idempotency-Key` + قيد فريد في القاعدة |
| رموز المتابعة | ٣٢ محرفًا عشوائيًا من `random_bytes` + صلاحية محدودة |

## 10. النسخ الاحتياطي والاستعادة

### من اللوحة

**الأمان والنسخ ← إنشاء نسخة الآن** ثم **تنزيل**.
تُنشأ عبر `VACUUM INTO` — نسخة سليمة حتى أثناء عمل الموقع.

### من الطرفية

```bash
php bin/console backup      # ينشئ storage/backups/backup-YYYYmmdd-HHMMSS.sqlite
```

### نسخة يومية تلقائية

```cron
0 3 * * * cd /path/to/project && php bin/console backup > /dev/null
```

أضف سطرًا ثانيًا إلى **تنظيف النسخ القديمة** (اترك آخر ٣٠ يومًا):

```cron
0 4 * * * find /path/to/project/private-data -name 'backup-*.sqlite' -mtime +30 -delete
```

> 💡 لو حذفت `bin/` في مرحلة التنظيف، احتفظ بنسخة من الأمر في
> `crontab` عبر استدعاء PHP مباشر — أو أعد رفع `bin/console` لأمر النسخ فقط.

### الاستعادة

1. أوقف الاستقبال مؤقتًا (اختياري لكن أفضل).
2. انسخ ملف النسخة إلى مكان قاعدة البيانات (انظر `db.path` في `local.php`).
3. احذف `app.sqlite-wal` و `app.sqlite-shm` إن وُجدا.
4. أعد التشغيل، ثم تحقّق: `php bin/console status`.

> ⚠️ **استعد على بيئة staging أولًا.** نسخة من تصحيح سعر خاطئ
> تُطبَّق مباشرة = تكرار الخطأ على كل طلب.

## 11. التحديث إلى نسخة القالب الأحدث

### قاعدة رقم الإصدار

رقم واحد في `ProjectConfig::VERSION` هو المرجع، لكن لا بد من مزامنته
في **أربعة مواضع** دفعة واحدة:

| # | الملف | ما يُحدَّث |
| --- | --- | --- |
| 1 | `src/Config/ProjectConfig.php` | `VERSION` و `RELEASED_AT` |
| 2 | `app/index.html` | ٥ مواضع `?v=1.3.0` (CSS + ٤ سكربتات) |
| 3 | `sw.js` | ثابت `VERSION` (بلا حرف `v`) |
| 4 | `CHANGELOG.md` | قسم الإصدار الجديد |

> 🔒 **الاختبار `pwa` يفشل إن غيّرت بعضًا دون بعض** — فهو يتحقق أن الأرقام
> متطابقة. حارسك هنا، لا اعتمد على الذاكرة.

### كيف يعمل التحديث عمليًا؟

```
ترفع الملفات الجديدة
      ↓
sw.js جديد → يُ.downloaded لكنه ينتظر
      ↓
الصفحة تُغلق وتُفتح (أو كل العملاء يفتحون الموقع)
      ↓
activate يحذف كل كاش قديم باسم مختلف
```

| ما زال الموقع يعرض النسخة القديمة؟ | الحل |
| --- | --- |
| على المتصفح نفسه | أغلق تبويب الموقع تمامًا وافتحه من جديد |
| على المتصفح نفسه | جرّب من نافذة خاصة (Private) لتتجاهل الكاش |
| على جهاز آخر؟ | إن كان يعمل: الكاش عندك · وإن كان لا: الخادم |
| بعد كل المحاولات | أعد رفع الملفات وتأكد أن رقم الإصدار تغيّر فعلًا |

> ⚠️ **لماذا يتأخر التحديث؟**
> عامل الخدمة لا يستبدل نفسه وهو مُتحكَّم به. هذا سلوك صحيح في PWA
> وليس عطلًا. لذلك يُخزَّن CSS و JS **أسبوعًا كاملًا** على الخادم،
> ولهذا السبب وجوب ترقيم `?v=` ليس تفصيلًا تجميليًا.

### ترقية بأمان

```bash
# 1) نسخة احتياطية قبل أي تعديل — إجباري
php tools/audit-backup.php

# 2) احفظ تخصيصاتك (ملف company.json + تعديلات ProjectConfig)
cp app/data/company.json  ~/my-company.json
cp src/Config/ProjectConfig.php ~/my-ProjectConfig.php

# 3) ارفع ملفات القالب الجديدة فوق النسخة القديمة (بلا حذف)
#    — لا تحذف storage/ ولا app/uploads/ ولا local.php

# 4) حدّث المخطط
php bin/console migrate

# 5) اختبر
php tests/run.php

# 6) أعد التخصيصات، ثم رقّم الإصدار في المواضع الأربعة
```

> ⚠️ **لا ترفع ملفات القالب فوق `storage/`.**
> قاعدة البيانات والملف السري والصور المرفوعة لا تُلمس أبدًا.
> `tools/audit-backup.php` يؤخذ هذه الخطوة نيابةً عنك.

### قائمة ما لا يُنسخ

| الملف | السبب |
| --- | --- |
| `storage/config/local.php` | فيه كلمة مرورك ورابط موقعك |
| `storage/database/app.sqlite` | طلباتك ومنتجاتك |
| `storage/backups/` | نسخك الاحتياطية |
| `app/uploads/` | صور المنتجات |
| `app/data/company.json` | محتواك (يعاد تطبيقه من نسختك) |

## 12. استكشاف الأخطاء

| العرض | السبب | الحل |
| --- | --- | --- |
| الصفحة تحوّلني إلى `setup` | `local.php` غير موجود | `php bin/console install` |
| «حدث خطأ في الخادم» بعد التحديث | مخطط القاعدة قديم | `php bin/console migrate` |
| روابط `/cart` تعطي 404 | الخادم لا يوجّه المسارات | Apache: فعّل `mod_rewrite` · nginx: `try_files` |
| الروابط نظيفة معطّلة فعلًا | الخادم بلا إعدادات | التطبيق يتحوّل تلقائيًا لوضع الهاش `/#/cart` |
| رموز QR لا تعمل | `base_url` غير حقيقي | صحّحه في `storage/config/local.php` وأعد التوليد |
| «تم إيقاف المحاولات مؤقتًا» | ٦ محاولات فاشلة | انتظر ١٥ دقيقة أو: `php -r "…Database::delete('login_attempts','1 = 1');"` |
| الصور لا تظهر | صلاحيات أو نوع MIME | `chmod -R 775 app/uploads` |
| ترميز عربي مشوّه | ترميز ملف خاطئ | احفظ الملفات UTF-8 **دون BOM** |
| «لا يوجد اتصال» مع وجود إنترنت | الخادم متعطّل | راجع `storage/logs/app-YYYY-MM-DD.log` |
| البحث لا يجد منتجًا | الحقل غير `searchable` | اجعل `searchable: true` في تعريفه |
| زر «أضف» لا يظهر في وضع العرض | هذا سلوك مقصود | بدّله بـ `store` أو `clinic` |

> 🔍 **كل الأخطاء تُسجَّل.** ابدأ دائمًا من:
> `storage/logs/app-YYYY-MM-DD.log`

## الخلاصة

القالب مصمّم ليفصل **ثلاثة أشياء** كانت عادة مدمجة في مشروع واحد:

1. **المحتوى** في ملف واحد — تتغير هويتك دون لمس الكود.
2. **السلوك** في اختيار واحد — تتغيّر التسميات والوضع كاملًا.
3. **البنية** في كلاس واحد — تُعدَّل حين لا يكفي ما سبق.

احترم هذا الفصل، وستحصل على مشروع **يمكن صيانته بعد سنوات** دون أن
يبدو كملفات متراكمة لا يعرف أحد سبب وجودها.

وعندك السؤال الأبسط: **ما الطبقة التي تخصّ سؤالي؟** المحتوى أم السلوك
أم البنية؟ ابدأ من هناك.
